# Как я понял функционал бота

## Назначение
Бот — юридический ассистент в Telegram (личные чаты), который отвечает на вопросы по кодексам и смежным правовым темам на основе базы статей и LLM.

## Ключевые сценарии
- Текстовый запрос пользователя -> поиск релевантных статей -> генерация ответа.
- Голосовой запрос -> STT (распознавание) -> поиск/генерация -> текстовый и голосовой ответ.
- Фото/скрин документа -> vision-анализ -> текстовый ответ с юридическим разбором.

## Источники данных и поиск
- Векторная БД ChromaDB с embeddings по статьям.
- Поиск top-N статей по embedding-запросу с фильтрами (например, по стране).
- Фильтрация результатов по distance для повышения релевантности.

## Работа с контекстом диалога
- Бот должен удерживать контекст разговора между сообщениями пользователя.
- Короткие реплики (например, "да", "РФ", "про нее") интерпретируются как продолжение предыдущей темы.
- При неоднозначности бот должен уточнять, правильно ли понял задачу и к какому вопросу относится текущий запрос.

## Ответы и поведение LLM
- Генерация ответов через Grok/OpenAI-совместимый интерфейс.
- Ответы должны ссылаться на страну, кодекс и статью, когда это возможно.
- При недостатке релевантных данных бот не выдумывает факты, а сообщает о нехватке данных и просит уточнение.

## Голосовые технологии
- STT для входящих голосовых сообщений.
- TTS для озвучивания ответа.
- Поддержка переключаемого TTS-провайдера через env-конфиг.

## Продуктовые функции
- Платежи и лимиты (бесплатный режим + подписка).
- Мультиязычный интерфейс (RU/EN).
- Логирование действий, событий и ошибок.
- Защита от подозрительных запросов и базовый rate limiting.

## Нефункциональные ожидания
- Устойчивость к "кривым" запросам и ошибкам форматирования.
- Стабильная работа при большом количестве пользователей.
- Прозрачное поведение: лучше уточнить вопрос, чем дать потенциально неверный ответ.
