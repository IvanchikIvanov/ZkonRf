# Что я изменил в коде

Ниже перечислены изменения, которые я внес в рамках этой сессии.

## 1) TTS: добавлен второй провайдер и переключение через env
- Файл: `bot/services/tts_service.py`
  - Добавил `TTS_PROVIDER`-based роутинг:
    - `chatgpt` / `openai` -> OpenAI TTS.
    - `elevenlabs` -> ElevenLabs TTS.
  - Добавил fail-fast проверки обязательных ключей для выбранного провайдера.
  - Исправил генерацию ElevenLabs: `output_format` вынесен в настройку и теперь валидный.
  - Разделил кэш TTS по провайдеру/модели/голосу, чтобы не было коллизий.
- Файлы: `bot/utils/config.py`, `env.example`
  - Добавлены настройки:
    - `TTS_PROVIDER`
    - `ELEVENLABS_OUTPUT_FORMAT`
  - Обновлены значения по умолчанию и комментарии.
- Файл: `requirements.txt`
  - Зафиксирована версия `elevenlabs` для стабильности среды.

## 2) Удален дублирующий GitHub workflow деплоя
- Файл удален: `.github/workflows/deploy.yml`
- Оставлен один рабочий пайплайн: `.github/workflows/deploy-railway.yml`

## 3) Контекст диалога: перевод на постоянное хранение (без TTL)
- Файл: `bot/services/conversation_context.py`
  - Перенес хранение контекста из Redis-кэша в SQLite-таблицу `conversation_messages`.
  - История сохраняется бессрочно (до явного `clear_context`).
  - Добавил инициализацию таблицы и индекс.
  - Добавил параметры окна:
    - сколько сообщений отправлять в промпт;
    - сколько сообщений сканировать для извлечения страны/кодекса;
    - максимальная длина одного сообщения в истории.
  - При извлечении контекста повысил приоритет пользовательских сообщений.
- Файлы: `bot/utils/config.py`, `env.example`
  - Добавлены настройки:
    - `CONTEXT_PROMPT_MESSAGES`
    - `CONTEXT_SCAN_MESSAGES`
    - `CONTEXT_MAX_CONTENT_LENGTH`

## 4) Поведение LLM для неоднозначных запросов + исправление кэш-ключа
- Файл: `bot/services/llm_service.py`
  - Добавил инструкцию "сначала подтвердить понимание запроса".
  - Добавил требование задавать уточняющий вопрос при неоднозначности.
  - Исправил `cache_key` LLM: теперь учитывается контекст, модель и параметры генерации.

## 5) Корректный учет запросов (лимиты/биллинг)
- Файлы: `bot/handlers/text_handler.py`, `bot/handlers/voice_handler.py`, `bot/handlers/photo_handler.py`
  - Перенес `increment_request(...)` на этап после успешной отправки ответа пользователю.
  - Это убирает списание запроса при внутренних ошибках до ответа.

## 6) Устойчивость отправки ответов
- Файлы: `bot/handlers/text_handler.py`, `bot/handlers/voice_handler.py`, `bot/handlers/photo_handler.py`
  - Добавил fallback:
    - сначала попытка `parse_mode="Markdown"`;
    - при ошибке отправка plain-text ответа.

## 7) Исправления обработки голоса/фото
- Файл: `bot/handlers/voice_handler.py`
  - Для коротких голосовых уточнений включил валидацию с учетом наличия контекста (`allow_short_with_context`).
- Файл: `bot/handlers/photo_handler.py`
  - Исправил баг: `caption` теперь определяется до первого использования.

## 8) Rate limiter под нагрузку по числу пользователей
- Файл: `bot/services/rate_limiter.py`
  - Добавил очистку неактивных пользователей из in-memory структур.
  - Это ограничивает рост памяти при большом количестве уникальных user_id.

## 9) Проверки после изменений
- Запускал компиляцию Python-модулей (`compileall`) по измененным файлам.
- Проверял диагностикой линтера измененные файлы.
- Критических ошибок после внесенных правок не найдено.
