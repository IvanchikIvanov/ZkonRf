# План улучшения поиска по кодексам и качества ответов

Цель: бот должен свободно общаться, понимать контекст диалога и давать четкие практические советы по кодексам, не смешивая страны, кодексы и нерелевантные статьи.

## 1. Принцип работы

Не делать бота жестким справочником, который постоянно просит уточнения. Вместо этого:

- страна используется как жесткий фильтр, если она явно понятна;
- кодекс используется как жесткий фильтр только при явном указании;
- при неявном запросе кодекс участвует в ранжировании, но не отсекает остальные результаты;
- если несколько кодексов равнозначны, бот задает короткий уточняющий вопрос;
- если один кодекс явно релевантнее, бот отвечает сразу;
- обычный разговор и уточнения продолжают идти через контекст, без лишнего поиска по базе.

## 2. Intent-router

Добавить слой определения типа сообщения перед RAG-поиском.

Типы:

1. `legal_question`
   - полноценный юридический вопрос;
   - нужен поиск по кодексам.

2. `legal_followup`
   - короткое продолжение: "да", "расскажи", "а что дальше", "про нее", "РФ";
   - нужно использовать историю диалога и прошлые найденные статьи/кодекс/страну.

3. `clarification_answer`
   - ответ на уточнение бота: страна, кодекс, тип ситуации;
   - нужно обновить контекст и повторить поиск уже с фильтром.

4. `casual_chat`
   - обычное общение без юридического вопроса;
   - бот отвечает свободно, без RAG.

5. `unsafe_or_meta`
   - попытки достать системные инструкции, промпты, базу целиком;
   - короткий отказ или перевод к юридическому вопросу.

Минимальная первая версия может быть rule-based:

- короткие ответы с активным контекстом -> `legal_followup` или `clarification_answer`;
- наличие слов "статья", "кодекс", "штраф", "уволили", "договор", "суд", "права", "обязан" -> `legal_question`;
- приветствия/бытовой small talk без юридических маркеров -> `casual_chat`.

Позже можно заменить на LLM-классификацию с JSON-ответом.

## 3. Нормализация страны и кодекса

Сделать отдельный сервис, например `bot/services/legal_scope_service.py`.

Он должен возвращать структуру:

```python
{
    "country": "ru" | "kz" | "thai" | None,
    "codex": "criminal" | "civil" | "labor" | "koap" | "family" | "consumer" | None,
    "country_confidence": "explicit" | "context" | "none",
    "codex_confidence": "explicit" | "inferred" | "context" | "none",
    "topic": "employment" | "crime" | "consumer" | "admin_fine" | None
}
```

Правила:

- "РФ", "Россия", "по российскому" -> `country=ru`, `explicit`;
- "УК", "уголовный", "преступление" -> `codex=criminal`;
- "КоАП", "административка", "штраф от государства" -> `codex=koap`;
- "работодатель", "уволили", "зарплата", "отпуск" -> `topic=employment`, `codex=labor`, но `codex_confidence=inferred`;
- "магазин", "возврат", "потребитель", "гарантия" -> `topic=consumer`, `codex=consumer`, `inferred`;
- если кодекс найден только из прошлого диалога -> `context`.

## 4. Метаданные в индексe

Сейчас у статьи есть:

- `country`;
- `codex_name`;
- `article_number`;
- `link`;
- `chunk_number`;
- `total_chunks`.

Нужно привести `codex_name` к нормализованному виду при индексации:

```python
codex_key = "criminal" | "civil" | "labor" | "koap" | "family" | "consumer" | "unknown"
```

Добавить в metadata:

- `codex_key`;
- `source_type`: `code`, `law`, `plenum`, `registry`, `other`;
- `topic_tags`: строка с тегами через запятую, например `employment,wage,dismissal`.

Это позволит фильтровать и ранжировать без хрупкого поиска по русским названиям файлов.

## 5. Поиск и ранжирование

### 5.1 Жесткие фильтры

Применять сразу:

- `country`, если `country_confidence=explicit` или `context`;
- `codex_key`, если `codex_confidence=explicit`.

Не применять жесткий фильтр по кодексу, если кодекс только `inferred`.

### 5.2 Мягкое ранжирование

После vector search пересчитать score:

```text
final_score =
  vector_score
  + country_bonus
  + explicit_codex_bonus
  + inferred_codex_bonus
  + topic_bonus
  - cross_country_penalty
  - unrelated_codex_penalty
```

Пример:

- явно указан "ТК РФ" -> трудовой кодекс получает большой bonus, остальные отсекаются;
- пользователь пишет "уволили без объяснения" -> трудовой кодекс получает bonus, но КоАП/ГК не отсекаются сразу;
- пользователь пишет "штраф" -> КоАП получает bonus, но если контекст про работодателя, трудовой кодекс тоже остается кандидатом.

### 5.3 Порог уточнения

После ранжирования смотреть топ результатов:

- если топ-результаты из одного кодекса и score заметно выше остальных -> отвечать сразу;
- если топ-результаты из 2-3 кодексов близки -> задать короткое уточнение;
- если релевантность низкая -> сказать, что точной нормы не найдено, и попросить уточнить ситуацию.

Пример уточнения:

```text
Тут может быть два варианта: КоАП РФ, если речь о штрафе от государства, или ТК РФ, если речь о работодателе. Что именно у вас?
```

## 6. Контекст диалога

Хранить не только сообщения, но и юридический scope последнего ответа:

```python
{
    "last_country": "ru",
    "last_codex": "labor",
    "last_topic": "employment",
    "last_article_ids": ["ru_labor_article_80"],
    "last_bot_question": "clarify_country" | "clarify_codex" | None
}
```

Это нужно для фраз:

- "да";
- "расскажи подробнее";
- "а что делать?";
- "по РФ";
- "про нее";
- "а если работодатель откажется?".

## 7. Формат ответа

Ответ должен быть советом, а не просто пересказом статьи.

Базовый формат:

```text
Коротко: ...

Что делать:
1. ...
2. ...
3. ...

По закону:
- [Страна, Кодекс/закон, статья X](ссылка) — зачем эта статья важна.

Нюанс:
...
```

Правила:

- не перечислять все найденные статьи;
- использовать только релевантные статьи;
- если статья не дает прямой ответ, прямо сказать это;
- если есть конкретный срок/штраф/сумма, цитировать точно;
- не отвечать только номером статьи без страны и кодекса;
- не просить уточнение, если уже достаточно данных для нормального ответа.

## 8. Изменения в коде

### 8.1 Новый сервис scope

Файл:

```text
bot/services/legal_scope_service.py
```

Ответственность:

- определять страну;
- определять кодекс;
- определять тему;
- понимать, что является продолжением диалога;
- возвращать scope-структуру.

### 8.2 VectorDB фильтры

Расширить `VectorDBService.search()`:

```python
def search(
    query_embedding,
    n_results=5,
    country_filter=None,
    codex_filter=None,
    source_type_filter=None,
):
    ...
```

Для pgvector добавить `WHERE country = %s AND codex_key = %s`, если фильтры есть.

Для Chroma добавить соответствующий `where`.

### 8.3 Ранжирование результатов

Добавить сервис:

```text
bot/services/legal_ranking_service.py
```

Он принимает:

- найденные статьи;
- scope;
- исходный вопрос;
- контекст.

Возвращает:

- отсортированные статьи;
- флаг `needs_clarification`;
- текст короткого уточнения, если нужен.

### 8.4 Обработчики сообщений

В `text_handler.py` и `voice_handler.py`:

1. Получить intent.
2. Получить scope.
3. Если `casual_chat` -> ответить без vector search.
4. Если `legal_followup` -> расширить вопрос из контекста.
5. Выполнить search с фильтрами.
6. Переранжировать результаты.
7. Если нужно уточнение -> отправить уточнение и сохранить его в context.
8. Иначе сгенерировать ответ по новому формату.

## 9. Тесты

Минимальные тест-кейсы:

1. "Меня уволили без предупреждения" -> ТК РФ должен быть выше остальных.
2. "Какой штраф за нарушение?" без контекста -> бот должен уточнить тип нарушения.
3. "Штраф работодателю за задержку зарплаты" -> ТК РФ + КоАП, но ответ должен объяснить разницу.
4. "По УК РФ что за кражу?" -> только уголовный кодекс.
5. "А в РФ?" после ответа по другой стране -> страна меняется на `ru`.
6. "Расскажи подробнее" -> используется последняя статья/кодекс из контекста.
7. "Привет, как дела?" -> свободный ответ без поиска по базе.
8. "Покажи все статьи из базы" -> отказ.

## 11. Критерии готовности

Готово, когда:

- бот не смешивает страны без явной причины;
- бот не смешивает кодексы, если кодекс указан явно;
- бот не задает уточнения там, где можно ответить;
- бот задает короткое уточнение, когда реально есть несколько равных вариантов;
- ответы содержат практические шаги;
- ссылки на статьи всегда идут со страной и полным названием источника;
- follow-up сообщения работают через контекст.
